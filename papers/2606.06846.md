## Key idea

- 기존 가변 rate CSI 피드백은 학습된 latent를 정렬·마스킹·양자화해서 비트 수를 바꾼다. CsiCoGen은 이 대신 **reverse diffusion 궤적의 Gaussian innovation** 을 유한 코드북에서 고르고, 그 index를 피드백한다 (Sec. II, Fig. 1).
- UE와 BS가 같은 PRNG seed로 만든 Gaussian 코드북을 공유하므로 코드북은 전송하지 않는다. 길이 L의 prefix만 받아도 유효한 CSI 추정이 나와서 **prefix 길이로 payload를 조절**한다 (R_L = L·log2 K).
- denoiser는 공유 CSI prior로 미리 학습한다.

## System model

- FDD massive MIMO, angle–delay 영역 CSI (COST2100 표준 설정).
- UE가 BS와 같은 denoiser·schedule을 실행해 각 단계 innovation을 코드북에서 선택(encode), BS는 index로 같은 궤적을 재생(decode).

## Results (baseline 대비)

- outdoor NMSE **−13.96 dB @792 bits, −20.37 dB @1592 bits** (indoor −28.58 / −30.72 dB) (Abstract).
- 비교: OVQ-TransNet −9.24 dB @800 bits(outdoor), OFSQ-CRNet −5.04 dB @960 bits(outdoor) (Table I).
- 가속 sampler(D20/F200)는 처리량을 ≈ 10배(55 → 510 samples/s) 올리면서 outdoor NMSE −19.48 dB, SGCS 0.949 유지 (Table II).

## Limitations

- 저자도 인정하듯 **추론이 반복 diffusion이라 느리다**. one-shot AE/VQ보다 처리량이 수십–수백 배 낮다 (Table II).
- UE도 denoiser를 반복 실행해야 하므로 UE 복잡도가 크다. COST2100 단일 분포 평가라 일반화는 미검증.
- UE·BS가 denoiser·PRNG seed를 정확히 맞춰야 해서 inter-vendor 환경에서는 사실상 같은 모델 공유가 전제다.

## 우리 업무 관점 코멘트

- **RAN1#127 안건 대응: 9.1.1 (Case 0 CSI 압축).** prefix 길이만으로 payload를 바꾸는 방식은 Case 0의 payload 확장성 논의에 아이디어로 참고할 만하다. 다만 UE 쪽 반복 추론 비용 때문에 그대로 표준 후보가 되기는 어렵다.
- 양쪽이 같은 denoiser를 써야 하는 구조라 9.1.2의 "어느 쪽이 무엇을 공유하나" 관점에서는 Type 1(한쪽 학습 후 배포)에 가깝다.
- COST2100 결과라 우리 38.901 평가와 직접 비교는 어렵다.
