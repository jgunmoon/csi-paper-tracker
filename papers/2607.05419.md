## Key idea

- 3GPP Rel-18 AI/ML CSI 압축 평가에 쓰인 baseline(encoder–양자화–transformer decoder)에 **Contrastive Predictive Coding(CPC)** 을 붙여, 압축과 시간축 예측을 한 모델에서 학습한다 (Sec. III, Fig. 2).
- CPC-before-Compression은 원 CSI 특징에서 미래 latent를 예측하고, CPC-after-Compression은 압축된 표현 위에서 예측한다. 손실은 1−SGCS + InfoNCE 가중합 (식 (5)).
- 고차원 CSI 행렬 대신 **미래 latent 표현**을 예측하므로, BS가 추가 복원 비용 없이 미래 CSI 추정을 얻는다는 주장 (Sec. VI).

## System model

- FDD, UE가 CSI(32 antenna port × 13 subband)를 압축해 64 bits로 피드백, gNB가 복원 (Sec. V).
- 시간축: 2–20 step 예측 horizon에서 latent 예측 (Sec. V–VI).

## Results (baseline 대비)

- CPC-before-Compression: SGCS가 대부분 0.90 이상이고, **decoder GFLOPs가 3GPP baseline의 1/32** (Abstract, Sec. VI).
- 대신 UE 쪽 encoder가 무겁다: 10.6M 파라미터, GFLOPs 10.47 vs baseline 0.59 (≈ 17.8배), baseline encoder는 872K·2.45 ms/batch (Table II).
- CPC-after-Compression: 3GPP baseline과 **같은 encoder·같은 64 bits**로 SGCS는 baseline과 비슷하고, horizon 2–20 step에서 거의 일정 (예: Nokia 0.677 → 0.675) (Sec. VI).
- 교차 데이터셋: Nokia·Oppo 모델은 서로 ≈ 0.73으로 일반화되지만, CATT 학습 모델은 다른 데이터셋에서 0.637–0.644로 떨어짐 (Table IV 서술).

## Limitations

- 3GPP 코드북(eType II)과의 비교가 없고, 비교 대상이 3GPP AI baseline 하나다.
- CPC-before는 decoder를 가볍게 하는 대신 **UE encoder를 크게 키운다** — UE 복잡도가 중요한 two-sided 배포 관점에서는 불리하다.
- 데이터셋이 회사 비공개라 그대로 재현하기 어렵다.

## 우리 업무 관점 코멘트

- **RAN1#127 안건 대응: 9.1.1 (Case 0 CSI 압축, 간접).** Case 0 baseline 구조와 3GPP 회사 데이터셋·SGCS를 그대로 써서, 우리 Case 0 평가 체계에 시간축 예측을 얹을 때의 참고 구현이 된다. 다만 Case 0 자체는 시간축을 제외하므로 다음 단계(시간축 포함 사례) 논의용이다.
- CPC-after-Compression은 encoder·payload를 바꾸지 않고 BS 쪽에서만 예측 기능을 얻는 구조라, **UE 모델은 그대로 두고 NW 모델만 확장**하는 inter-vendor 시나리오(9.1.2)와도 맞물린다.
- 코드가 공개되어 있어 우리 Case 0 데이터셋으로 SGCS를 다시 재 보기가 쉽다. CPC-before의 UE encoder 크기는 별도 확인이 필요하다.
