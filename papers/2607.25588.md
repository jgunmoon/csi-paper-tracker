## Key idea

- CR이 다른 **사전 학습 AE 여러 개를 고정해 두고**, 중앙 RL agent가 사용자별로 어떤 CR을 쓸지 매 시점 고른다 (Fig. 1).
- 보상은 MSE가 아니라 SINR 기반 SE, 피드백 overhead, AE 전환 비용을 함께 본다.
- AE를 다시 학습하지 않아 encoder–decoder 동기화 문제가 없다.

## System model

- 다중 사용자 MIMO FDD, 지연 영역 CSI, LoS·NLoS·blockage 시나리오 전환 (Sec. II, V).

## Simulation setup

| 항목 | 값 |
|---|---|
| 채널 모델 / 시나리오 | LoS / NLoS / blockage 데이터셋 (채널 모델 미확인) |
| 지표 | NMSE, 하향링크 합 전송률, 피드백 비용 |
| 코드·데이터 공개 | GitHub 코드 |

## Results (baseline 대비)

- 평균: 피드백 비용 **−53.4%**, 합 전송률 **+53.6%**, NMSE −22.4% (Sec. V).
- 규칙 기반 ATH 대비 비용 −55.8%·합 전송률 +5.7%, 지도학습 LAD 대비 비용 −57.5%·합 전송률 +124% (Sec. V).
- 시나리오 전환 뒤 회복이 baseline보다 빠르다 (Conclusion).

## Limitations

- 채널 모델이 명확하지 않고, 합 전송률 이득이 LAD 대비 +124%처럼 커서 baseline 구현 조건 확인이 필요하다.
- 3GPP 코드북·SGCS 비교 없음.

## 우리 업무 관점 코멘트

- **RAN1#127 안건 대응: 9.1.1 (Case 0, 다중 payload 모델 운용).** payload별 모델을 여러 개 두고 상황에 따라 고르는 방식은 Case 0의 "payload별 모델 vs 단일 가변 모델" 논의의 반대편 사례다.
- 모델 전환 비용을 보상에 넣은 점은 Rel-20 LCM(모델 활성화·전환) 논의와도 닿는다.
- 채널 조건이 불분명해 수치 인용보다는 구조 참고용이다.
