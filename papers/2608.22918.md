## Key idea

- two-sided AI 모델 연구가 흔히 깔고 있는 세 가정(기존 사용자와 분리, 정해진 채널 조건에서 학습, vendor 간 gradient 교환 fine-tuning)을 짚고 각각 대안을 제시하는 개관 논문 (Fig. 1).
- ① NR 프로토콜 스택 안에 two-sided 모델을 넣은 OTA 테스트베드, ② MCS 표처럼 미리 학습한 모델 표에서 고르는 적응형 모델 선택(AMS), ③ **스칼라 손실값만 주고받는 zeroth-order fine-tuning** 으로 vendor 간 gradient 교환을 없앤다 (Sec. II–V).

## System model

- CSI 피드백 부분: UE(vendor B) encoder – gNB(vendor A) decoder, 압축률 1/4 (Fig. 5).
- 테스트베드: OCUDU gNB + USRP B210, n78 20 MHz, 30 kHz SCS (Sec. II).

## Simulation setup

| 항목 | 값 |
|---|---|
| 채널 모델 / 시나리오 | CSI 실험: 미기재 · UL 데이터 실험: 38.901 RMa 1×4 |
| 지표 | NMSE, 메모리, 통신 overhead, throughput |
| Payload / 압축률 | 1/4 |
| 코드·데이터 공개 | 없음 |

## Results (baseline 대비)

- **Type 2 fine-tuning의 정보 노출**: vendor A가 교환된 gradient만으로 vendor B 쪽 Jacobian을 NMSE −58.24 dB, B 모델 출력을 −14.56 dB로 추정 (Sec. V).
- **gradient-free fine-tuning**: Type 2와 비슷한 복원 NMSE를 내면서 vendor A 메모리 3.65배, vendor B 통신 overhead 15,000배 이상 감소 (Fig. 5).
- UL 데이터 실험: 저 SNR에서 two-sided 모델이 기존 NR보다 throughput 4배 이상 (Sec. II).

## Limitations

- 개관 형식이라 CSI 실험의 채널 모델·데이터셋·양자화 등 조건이 거의 없다. 수치를 그대로 인용하기 어렵다.
- zeroth-order 방식은 수렴에 필요한 반복 수(=스칼라 교환 횟수)와 시간이 길 수 있는데, 그 비용은 따로 정리되어 있지 않다.

## 우리 업무 관점 코멘트

- **RAN1#127 안건 대응: 9.1.2 (two-sided 모델 inter-vendor 학습 협업).** Type 2(gradient 교환)가 상대 vendor 모델 정보를 노출한다는 정량 근거와, 스칼라만 주고받는 대안을 함께 제시해 9.1.2 업체 입장 논의에 직접 쓸 수 있다.
- 우리 입장 정리 시 "Type 2의 정보 노출 위험 vs Type 3(데이터셋 공유)의 부담"을 비교하는 근거 자료로 활용 가능.
- 조건이 미기재라 우리 데이터셋으로 gradient 노출 실험을 재현해 보는 것이 필요하다.
