## Key idea

- CSI를 **연속 latent 대신 이산 token**으로 표현하는 wireless foundation model. 인코더 출력을 여러 크기의 codebook
  ({8, 16, …, 256} codewords) 중 하나로 **vector quantization**하고, token index 자체를 피드백 메시지로 보낸다 (Sec. III–IV-A).
- codebook만 바꾸면 3–8 bits/token으로 **피드백 rate가 바뀌고**, 인코더와 디코더 backbone은 하나만 쓴다. 별도 양자화 단계가 필요 없다.
- 같은 token 공간 위에서 주파수 영역 CSI 예측(관측 안 된 subcarrier 추정), beam 예측, 측위, LoS/NLoS 식별 같은 downstream task를 적은 파라미터만 학습해 수행한다.

## System model

- 기지국 N_t = N_h × N_v 안테나 UPA, K subcarrier. 피드백 대상은 **채널 행렬 H 자체** (real/imag 쌓아 2 × N_t × K)이고 eigenvector/precoder가 아니다 (Sec. II-A).
- 피드백 비트 N_bit = L · ⌈log2 N_c⌉, L = N_t K / 16 (4 × 4 down-sampling) (식 (26)).
- 주파수 영역 예측: 관측 비율 0.25의 subcarrier로 나머지 영역을 예측하고, NMSE는 미관측 영역에서만 계산 (Sec. V-C).

## Results (baseline 대비)

- **3-bit ID 피드백 (Table III)**: 평균 NMSE **−15.713 dB**. 가장 강한 task-specific baseline인 TransNet보다 **5.299 dB**,
  foundation model baseline인 WiFo-CF(−9.391 dB)보다 **6.322 dB** 좋다. 모든 baseline이 같은 3L bits를 쓴다(TransNet은 3-bit uniform SQ, WiFo-CF는 3-bit μ-law, SG-VQ는 2+1 bit).
- **3-bit OOD 피드백, 제로샷 (Table IV)**: 평균 **−15.422 dB**. 해당 도메인으로 따로 학습한(full-shot) TransNet보다 **4.705 dB**,
  제로샷 WiFo-CF(−9.033 dB)보다 좋다.
- **Multi-rate (Fig. 3)**: 3-bit 대비 NMSE 이득이 4/5/6/7/8 bit에서 2.214/3.698/4.842/5.542/5.978 dB로 늘다가 포화한다 (그림 라벨 값).
- **주파수 영역 예측 (Fig. 5)**: 학습 샘플 200개에서 −5.776 dB로 Transformer-CP보다 1.676 dB, 연속 latent 버전(WiFo-D-Cont)보다 2.141 dB 좋다.
  1000개에서 −9.191 dB. 잡음이 섞인 관측에서는 WiFo-D-Cont 대비 이득이 SNR −5 dB 0.750 dB에서 20 dB 3.281 dB로 커진다 (Table VI).
- **복잡도 (Table IX)**: WiFo-D-Tiny는 0.263M 파라미터, 1.00 MB로 −13.003 dB. WiFo-D-Large는 15.999M, 61.03 MB, 지연 6.532 ms로,
  비슷한 크기의 WiFo-CF(14.183M, 41.279 ms)보다 빠르다. FLOPs는 더 크다 (RTX 5090, FP32).

## Limitations

- 피드백 대상이 **원 채널 행렬 H**이고 지표가 **NMSE뿐**이다. TR 38.843의 eigenvector 기반 피드백, SGCS, eType II 코드북 비교가 없어서 표준 평가와 바로 비교할 수 없다.
- 피드백 실험의 입력 CSI는 **잡음이 없는 정답 채널**(perfect CSI)이다. 잡음 강건성은 예측 실험에서만 봤다.
- subcarrier 16–64개, 대역폭 1 MHz 안팎의 작은 CSI 크기여서, NR 실제 설정(예: 32 포트 × 13 subband)으로 확장했을 때 이득이 유지되는지 확인이 필요하다.
- 피드백 링크의 비트 오류와 지연은 고려하지 않았다. 처리량 같은 최종 KPI도 없다.

## 우리 업무 관점 코멘트

- "codebook 선택만으로 payload 전환"은 Rel-19/20 two-sided 모델에서 **payload별 모델 수를 줄이는 방법**으로 의미가 있다.
  token index 피드백은 3GPP 보고 형식(UCI 비트열)과도 자연스럽게 맞는다.
- 반면 이산 codebook은 UE와 NW가 공유해야 하는 학습 산출물이라, 학습 협업 Type 2/3에서 codebook 동기화와 업데이트 절차를 따로 생각해야 한다.
- 재현하려면 QuaDRiGa 데이터셋 27개를 생성해야 하고 코드도 공개되지 않아 비용이 크다. 먼저 우리 38.901 데이터셋에서 eigenvector 피드백 + SGCS로 VQ 부분만 재현해 보기를 권한다.
