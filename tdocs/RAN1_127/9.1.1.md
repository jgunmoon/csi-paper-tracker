# RAN1#127 · 9.1.1 Case 0 CSI 압축 (two-sided 모델)

Rel-20에서 **시간축 없이 공간·주파수 영역만 압축하는 two-sided AI/ML CSI 피드백("Case 0")**의 규격을 만드는 안건이다.
다루는 범위: target CSI 형식, 측정·보고 설정, CQI/RI 결정, payload 결정, 양자화 설정, UCI 매핑, CSI 처리 시간, 보고 우선순위, NW 데이터 수집, 성능 모니터링 (세션 노트 [R1-2609130]).

## 지금까지의 합의 흐름

**RAN1#125** (의장 노트 eom)

- NW 측 데이터 수집용 target CSI 양자화: 복소수 원소마다 **진폭 3 bit + 위상 4 bit**, eType II 진폭·위상 양자화 표 재사용, 정규화 Alt2-1.
- UE 측 target CSI 제한(CBSR) 필요성은 **#126에서 결정**하기로 하고 비교 방법을 정함: Case A(제한 없음, NW가 복원 후 걸러냄) vs Case B(UE가 K개 빔을 제한), K=4 기준, 지표는 스펙트럼 효율/처리량.
- NW 데이터 수집에서 UE는 **NW가 설정한 rank 기준**으로 target CSI를 보고. 제안 rank·데이터 로깅 이벤트·데이터 품질 지표는 FFS.
- UE 측 데이터 수집 설정: Pairing ID(필수/선택 FFS), 측정 자원, 포트 설정(N1·N2, >32 포트는 port mapping), 서브밴드 설정.

**RAN1#126** (의장 노트 eom)

- **L3 시그널링 성능 모니터링**을 RAN2에 요청(LS): target CSI와 CSI 피드백 샘플 쌍 보고, 전체/일부 target CSI 허용, 여러 샘플 수집.
- **L1 시그널링 성능 모니터링** 지원 결정. 아래 4안 중 down-selection:
  Alt1 기존 eType II 형식(규격 영향 있음) / Alt2 NW 데이터 수집 형식의 target CSI 보고 / Alt3 UE가 SGCS·모니터링 결과 보고 / Alt4 기존 eType II(규격 영향 없음).
- 추론(inference) 설정 항목 확정: Pairing ID, 서브밴드, 측정 자원, portMappingMethod, `codebookConfig-r20`, payload 파라미터 조합, N1·N2, rank 제한. reportQuantity는 FFS.

**RAN1#126bis** (의장 노트 eom1)

- CQI: two-sided 모델 CSI 피드백에서 **CQI 계산의 RAN1 규격 영향 없음**(UE 구현). CQI 시험 요구사항은 RAN4 판단.
- NW 데이터 수집 설정 확정: 측정 자원(채널 측정 자원 필수), N1·N2, >32 포트 port mapping, **rank 설정(필수)**, 서브밴드. CBSR·데이터 품질·이벤트 관련 파라미터는 FFS.
- 추론 전용 처리: Rel-19 APU/CPU 틀 재사용(O_CPU,x x=2/3 또는 O_CPU,1, UE capability), 처리 시간 {Z+t', Z'+t'} (t'는 SCS별 UE capability, >32 포트는 Z2 또는 Z2·P32).

**RAN1#127** → 아래 절.

## RAN1#127 합의 사항

출처: 세션 노트 [R1-2609130] (최종, endorsed)

1. **L1 성능 모니터링 = UE의 1-bit 신뢰도 지시(reliability indicator)**
   - wideband, 모든 layer에 대해 1 bit ("0" 신뢰 불가 / "1" 신뢰). 값을 정하는 방법은 UE 구현.
   - 별도 UE capability.
2. **신뢰도 지시 보고 방식**
   - 추론과 같은 CSI 보고 설정에서 설정하고, 신뢰도+CSI(CQI, PMI, RI)용 **전용 report quantity 신설**. 1 bit는 CSI part 1 맨 끝.
   - AI/ML 전용 PU(O_CPU,x = X_x'', x=2 또는 3) 및/또는 기존 CPU(O_CPU,1 = X_1'') 점유, 값은 UE capability. 처리 시간 {Z+t'', Z'+t''}.
3. two-sided 모델 CSI 피드백에서는 **CRI·LI를 보고하지 않음** (`cri-RI-LI-PMI-CQI` 설정 안 함).
4. UE 측 데이터 수집의 CPU 점유 시간은 **Rel-19 CSI 예측과 동일 규칙** 재사용 (CSI-RS 시점부터 Z3' 심볼까지).
5. RAN2의 L3 모니터링 질의에 회신 [R1-2610956]: 모니터링은 near-real-time(수십 ms~수 초), 여러 샘플 로깅 여부는 RAN2가 결정, L1 이벤트 트리거는 합의 없음.
6. **결론 (합의 없음)**
   - UE 측 **target CSI 제한(CBSR)은 Rel-20에서 지원하지 않음**.
   - NW 데이터 수집에서 **제안 rank·데이터 품질 지표 보고, rank 기반 이벤트 정의 모두 지원하지 않음**.

## 남은 쟁점

- **잠재 벡터 양자화: SQ만 vs VQ 허용** — #127에서도 합의 없음. 아래 업체 입장이 거의 반반으로 갈림.
- **UE 측 데이터 수집의 Pairing ID 필수 여부**, 한 설정에 여러 Pairing ID 허용 여부 — 미결.
- CSI 보고 **우선순위 규칙**(기존 Pri_iCSI 재사용 시 k 값), UCI omission 규칙 — 미결.
- L1 모니터링은 1-bit 신뢰도 지시로 하나가 정해졌지만, NW 측 모니터링(Alt1/2/4)의 추가 지원 여부는 계속 논의 대상.

## 우리 업무 관점 코멘트

- **양자화가 다음 회의의 최대 쟁점**: VQ의 이득은 같은 payload에서 대체로 −1.6~+4%로 작고, 저 payload(10 bits/layer)에서만 +7% 수준이다. 우리 평가에서 VQ를 주장하려면 **저 payload 구간과 (d,Q) 조합을 함께 보고**해야 설득력이 있다(USTB 지적).
  트래커의 WiFo-D(2611.25378, 이산 token = VQ, multi-rate)가 이 논쟁과 직접 닿는다.
- **1-bit 신뢰도 지시 채택**: UE가 자기 모델 출력의 신뢰도를 판단하는 구현이 필요해졌다. UE 측 proxy 모델이나 SGCS 추정기 설계, 그리고 그 정확도 평가 방법(vivo의 |KPI 차이| 기준 등)을 준비할 필요가 있다.
- **CBSR 미지원 확정**: 셀 간 간섭 제어는 NW 측 필터링(Case A)에 맡겨진다. Qualcomm의 잔여 누설 41~58% 결과는 NW 측 필터링만으로는 한계가 있다는 근거라, 6GR(10.5.3.1)에서 다시 나올 수 있다.
- NW 데이터 수집에 부가 정보가 없으므로, NW 측 학습 데이터의 품질 관리(rank 불일치 샘플 처리 등)는 구현 몫으로 남았다.
