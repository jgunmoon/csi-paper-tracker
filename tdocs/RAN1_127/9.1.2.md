# RAN1#127 · 9.1.2 two-sided 모델의 업체 간 학습 협업

two-sided CSI 압축은 UE 쪽 encoder와 NW 쪽 decoder를 **서로 다른 업체가 만든다**. 이 안건은 둘을 맞추는 방법을 규격으로 정한다.

- **Direction A, Option 4-1**: NW가 **데이터셋**(target CSI + CSI 피드백)을 UE 업체에 넘기고, UE 업체가 그것으로 encoder를 학습.
- **Direction A, Option 3a-1**: 표준화된 encoder **모델 구조 + 파라미터**를 교환 (target CSI 없이).
- **Direction C**: 완전히 규격화된 참조 모델 (RAN4 중심).
- 데이터셋·파라미터 교환의 **신호 틀은 SA5(OAM)**, 교환 내용·형식은 RAN1(+RAN4)이 정한다. 세션 노트 기준 범위: 표준 데이터셋 형식·내용, 데이터셋 교환, pairing, RAN4 관련 사항.

**RAN1#127이 이 WI의 마지막 회의**였다 (FL summary [R1-2609843]).

## 지금까지의 합의 흐름

**RAN1#125** (의장 노트 eom)

- Option 4-1에서 교환하는 CSI 피드백 = **양자화 전 잠재 벡터를 float32**로 표현.
- CSI 피드백 집합의 layer 수 ≤ target CSI 집합의 layer 수.
- Option 4-1 성능 목표용 **SGCS 정의** 확정 (layer·payload 설정·서브밴드 평균, 평균과 X-percentile).
- SA5·RAN2에 pairing ID 관련 회신 LS.

**RAN1#126** (의장 노트 eom)

- Option 4-1 메타데이터에 **CSI 피드백 rank** 포함.
- Option 4-1 성능 목표용 **NMSE 정의** 확정, 성능 목표 형식은 float32.
- Option 3a-1: 교환하는 모델 파라미터와 함께 적용 가능한 설정(N1·N2, 서브밴드 크기, BWP 정보, layer당 payload, 서브밴드 설정, rank)을 제공.

**RAN1#126bis** (의장 노트 eom1)

- 추론 시 **모델 적용 가능성 절차는 Option A와 Option B 모두 지원** (Option B의 파라미터는 FFS).
- 결론: Option 4-1에서 payload 확장 방식(truncation/masking)을 알리는 추가 메타데이터는 **합의 없음**.
- RAN2 회신: Direction C 참조 모델의 pairing ID 값 개수는 RAN1 범위 밖.

**RAN1#127** → 아래 절.

## RAN1#127 합의 사항

출처: 세션 노트 [R1-2609130] (최종)

1. **Option B 추론 파라미터 확정** (Step 3의 otherConfig): Pairing ID, 서브밴드 설정, payload 설정(파라미터 조합), Tx 포트 설정(N1·N2), rank 제한(지원 rank). CSI-RS 자원 설정과 reportConfigType은 제외.
2. **Pairing 절차**: Option B는 후보 적용 가능 집합마다 pairing ID 1개, Option A는 추론용 CSI-ReportConfig마다 pairing ID 1개.
3. RAN2 LS 회신 [R1-2610936]: 위 1의 내용 전달 ("최대 rank" FFS를 "rank 제한 = 지원 rank"로 정리).
4. **결론 (합의 없음)**
   - >32 포트일 때 target CSI 메타데이터에 **집성 CSI-RS 자원 수·portMappingMethod 포함 안 함** (Option 4-1).
   - Option 3a-1 파라미터 적용 조합에도 **portMappingMethod 포함 안 함**.
   - Option 3a-1에서 모델 파라미터와 함께 **성능 목표(SGCS/NMSE) 제공 안 함**.
   - Option 4-1 target CSI에 NW 데이터 수집보다 **큰 (k1, k2) 쓰지 않음** → (3, 4) 유지.

## 남은 쟁점

- **교환 내용·형식을 어느 규격에 둘지**: RAN1 TS 38.215에 두고 SA5가 참조(Qualcomm, Panasonic, Ericsson, vivo 등) vs RAN1 규격에는 두지 않고 LS로 SA5·RAN2에 넘김(NTT DOCOMO, ZTE, NEC, Huawei). #127에서 결정되지 않았는데 WI 마지막 회의라 **처리 경로가 불투명**하다. SA5 WID(SP-260460)는 Option 4-1만 포함.
- VQ codebook 교환 형식(LUT 등)은 **9.1.1에서 VQ 지원이 정해진 뒤** 논의하기로 미룸 → 9.1.1 양자화 쟁점에 묶여 있음.
- Direction C 참조 encoder/decoder와 Option 3a-1 모델 파라미터 기술은 RAN4 몫(Ericsson은 RAN4에 LS 제안).

## 우리 업무 관점 코멘트

- **Rel-20 two-sided CSI의 실제 배포 경로는 Option 4-1(데이터셋 교환) 중심**이 됐다. SA5 WID도 4-1만 다룬다. 우리 쪽 준비는 NW 데이터셋 형식(target CSI (3,4) SQ, float32 피드백, rank·SGCS/NMSE 메타데이터)을 받아 encoder를 학습·검증하는 파이프라인이 핵심이다.
- **포트 순서·배치가 맞지 않으면 성능이 무너진다**(Fraunhofer). 메타데이터에 portMappingMethod가 빠졌으므로, 38.211의 포트 순서(p′)를 따른다는 전제를 우리 데이터 수집·학습 코드에 명시적으로 고정해야 한다.
- 성능 목표(SGCS)는 평가 모집단에 따라 0.03 이상 달라질 수 있어, NW가 준 목표치와 비교할 때는 **평균보다 하위 percentile**을 함께 봐야 한다(Pengcheng).
- 규격 위치(38.215 vs SA5) 미결은 Rel-20 마무리 일정의 위험 요소다. 다음 RAN 총회·SA5 결과를 확인할 필요가 있다.
